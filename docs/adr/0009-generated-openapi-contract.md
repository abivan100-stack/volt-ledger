# Generated OpenAPI contract from shared Zod schemas

Volt publishes a versioned OpenAPI 3.1 description of `/api/v1` that is generated from the same Zod objects the API uses at runtime, never hand-written. Request schemas live in `server/src/http/schemas.ts` and are parsed by the route handlers; response schemas live in `server/src/http/responses.ts` and are enforced by contract tests that parse real responses from the running app. Both sets feed `server/src/openapi/document.ts`, so the published contract cannot describe an API that no longer exists. `docs/openapi.json` is committed and regenerated with `npm run openapi:write`, and CI fails when it drifts from the code, so a change to a route or a schema must land together with its contract diff.

Runtime validation deliberately stays inside the handlers rather than moving to Fastify's `schema` option, even though that would be the more conventional single source. Two things depend on it. Which part of a request failed decides the error code — `INVALID_ORGANISATION_ID`, `INVALID_MEMBERSHIP_ID`, `INVALID_SIMULATION_ID`, `INVALID_INVITATION_ID`, `INVALID_AUDIT_CURSOR` — and a single schema-level rejection cannot express that distinction. And several Zod behaviours that JSON Schema and AJV cannot reproduce are load-bearing: `.trim()` transforms, `z.coerce` on query strings, `.default()` application, `.strict()` rejection of unknown keys, and the cross-field `.refine()` requiring an adjustment to change energy or credit. Routing validation through AJV would silently alter parsing while appearing equivalent. Sharing the schema objects gives the same single-source guarantee without that risk; rules JSON Schema cannot state — settlement and adjustment idempotency, that a correction never modifies its target, and how the opaque audit cursor behaves — are stated in prose on the operations they govern.

Targeting OpenAPI 3.1 rather than 3.0 is what makes the generation lossless: 3.1 uses JSON Schema 2020-12 unmodified, which is the dialect Zod emits, so nullable unions and `const` survive without translation. Coverage is verified in both directions against the running Fastify app, so neither an undocumented route nor a documented phantom can survive review.
