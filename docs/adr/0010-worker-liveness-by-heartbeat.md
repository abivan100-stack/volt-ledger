# Worker liveness by heartbeat

The simulation worker runs as its own process with no HTTP surface, so nothing can ask it whether it is alive. It reports instead: the loop keeps a `WorkerHealthSnapshot` — status, start time, last successful poll, consecutive failures, runs processed, last error code — and publishes it to an injected sink, which the entry point binds to a `worker_heartbeats` row keyed by `WORKER_ID`. Without this, a worker that has crashed and a worker with an empty queue are indistinguishable from the outside, and the difference is the one that matters at three in the morning.

Health and liveness are deliberately separate questions. A worker failing every poll is unhealthy but very much alive, and reporting it as alive is the point — the failure becomes visible rather than being mistaken for a dead process, and an operator learns to look at the database rather than at the supervisor. `deriveWorkerLiveness` therefore reads a stored beat as `live` while it is recent whatever its status, `stopped` when the worker said so however old the record is, and `stale` only on silence, because a killed process never got to write anything. Readiness is stricter than either: `isWorkerReady` is true only for `healthy`, since a worker retrying its way through a Mongo outage should not be counted on to drain the queue.

The heartbeat is state, not history, so it is written as an upsert on a single row per worker rather than appended to. This is not a departure from the ledger's append-only rule, which governs settlements and adjustments — evidence about energy and money that must never be rewritten. Only the latest beat answers "is it running right now", and a stream of them would grow without bound for no gain. The start time is rewritten on each beat rather than preserved on insert, because a restart is exactly what an operator needs to see.

No free-form error text is persisted. `describeErrorCode` accepts an explicit `code`, accepts a message only when the message is itself a code in `THIS_SHAPE`, and otherwise degrades to the error's class name — never the message and never a non-`Error` value. Driver failures routinely quote the connection string that failed, which is a credential, and unlike a log line this document is read back by other services.

Publishing is throttled but never gates the work. A change of status goes out immediately, an unchanged status is rate-limited so an idle worker does not write once per poll, and a sink that throws is logged as `worker.heartbeat_failed` and dropped without counting as a poll failure. The loop is decoupled from storage the same way it is from its clock and its logger, which is what lets the whole publishing path be tested without a database.
